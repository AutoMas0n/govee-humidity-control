## Purpose

Capture, analyze, and document the real H5080 BLE control protocol by sniffing traffic generated by the official Govee app while it toggles the plug.

## ADDED Requirements

### Requirement: Capture raw BLE traffic between Pi and plug

The system SHALL record all HCI-level BLE packets exchanged between the Raspberry Pi and the H5080 plug during a Govee app control session.

#### Scenario: btmon capture session

- **WHEN** the user runs `btmon -w /tmp/h5080_sniff.hci` on the Pi and the Govee app toggles the plug ON
- **THEN** the system SHALL record all HCI events and commands related to that device interaction to a file

#### Scenario: Capture includes connect, pair, and write

- **WHEN** full session is captured from app launch through plug toggle
- **THEN** the capture file SHALL contain all HCI packets: connection setup, pairing/bonding (if any), GATT service discovery, characteristic writes, and notifications

### Requirement: Parse captured packets into readable format

The system SHALL convert raw HCI captures into a human-readable dump showing BLE protocol details.

#### Scenario: hcidump readable output

- **WHEN** the user runs `hcidump -r /tmp/h5080_sniff.hci -x`
- **THEN** the output SHALL show packet direction, timing, ATT opcodes, attribute handles, and payload bytes

### Requirement: Identify the exact write characteristic

The system SHALL identify which GATT characteristic the Govee app writes to for power commands.

#### Scenario: Write characteristic identified from capture

- **WHEN** analyzing the capture
- **THEN** the system SHALL record the UUID and handle of every characteristic the app writes to during the toggle

### Requirement: Document the power command format

The system SHALL extract and document the exact byte sequence(s) the app sends for power ON and power OFF.

#### Scenario: Power ON bytes extracted

- **WHEN** the user toggles the plug ON in the Govee app
- **THEN** the system SHALL extract the exact write payload bytes from the capture

#### Scenario: Power OFF bytes extracted

- **WHEN** the user toggles the plug OFF in the Govee app
- **THEN** the system SHALL extract the exact write payload bytes from the capture

### Requirement: Replay captured commands to confirm

The system SHALL replay the captured command bytes to the plug and verify the relay toggles.

#### Scenario: Replay succeeds

- **WHEN** the captured ON bytes are written to the H5080 via `gatttool` or `bleak`
- **THEN** the plug relay SHALL close (ON)

#### Scenario: Replay confirms protocol

- **WHEN** both ON and OFF captured bytes are replayed
- **THEN** both SHALL toggle the relay, confirming the protocol is correct

### Requirement: Document any pairing or bonding sequence

If the app pairs with the plug before toggling, the system SHALL document that sequence.

#### Scenario: Pairing observed in capture

- **WHEN** the capture shows pairing commands (authentication requests, key exchanges) before the first write
- **THEN** the system SHALL document the pairing method and any persistent keys stored
